# Бриф на фотосъёмку

Пошаговая анкета для клиентов: 7 этапов по 3–5 вопросов, черновик сохраняется сам,
ответы приходят в Telegram отдельными сообщениями.

Статика без сборки: `index.html`, `styles.css`, `app.js`, `config.js` + папка `assets`.

| Файл | Что внутри |
|---|---|
| `index.html` | разметка: интро, этапы, финальный экран, подвал |
| `styles.css` | оформление в стиле основного сайта |
| `app.js` | логика; **этапы и вопросы — массивами в начале файла** |
| `config.js` | только адрес приёмника (Cloudflare Worker) |
| `worker.js` | код для Cloudflare, на сайт не загружается (можно, он не мешает) |
| `assets/fonts` | шрифты Wulkan Display и Inter с основного сайта |
| `assets/photo.jpg` | ваша фотография для экрана «Спасибо!» |

---

## 1. Фотография на финальном экране

Положите фото в `assets/photo.jpg`. Если файл называется иначе — поменяйте путь
в `index.html` (ищите `assets/photo.jpg`). Фото показывается целиком, без обрезки.
Пока файла нет, на его месте аккуратная заглушка.

## 2. Как работает отправка

- **`config.js` пустой** → после заполнения клиенту предлагается скачать файл
  с ответами, скопировать текст или написать вам в Telegram. Так можно запускать
  бриф уже сейчас.
- **В `config.js` указан адрес Worker** → ответы уходят в Telegram.
- **Если отправка не удалась** (нет сети, Worker недоступен) → клиент видит окно
  «Попробовать ещё раз / Скачать ответы / Написать в Telegram». Черновик при этом
  не удаляется: ответы остаются в браузере, пока бриф не дойдёт.

Черновик хранится в браузере клиента: ответы — в `localStorage`, приложенные файлы —
в IndexedDB. Закрыл вкладку — вернулся — всё на месте, с уведомлением
«Черновик восстановлен».

## 3. Подключение Telegram-бота

### Шаг 1. Создать бота
1. Откройте в Telegram **@BotFather** → `/newbot`.
2. Придумайте имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт **токен** вида `1234567890:AA...`. Никому его не показывайте.

### Шаг 2. Узнать chat_id
1. Найдите своего бота, нажмите **Start** и напишите ему любое сообщение.
2. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`.
3. Найдите `"chat":{"id":123456789` — это и есть `CHAT_ID`.

> Хотите получать брифы в группу (например, вместе с ассистентом)? Добавьте бота
> в группу, напишите там сообщение и снова откройте `getUpdates` — id группы
> начинается с минуса.

### Шаг 3. Создать Cloudflare Worker
1. Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com) (бесплатно).
2. **Workers & Pages → Create → Create Worker** → назовите, например, `lisa-brief` → **Deploy**.
3. **Edit code** → удалите всё и вставьте содержимое `worker.js` → **Deploy**.
4. **Settings → Variables and Secrets → Add**:
   - `BOT_TOKEN` — токен бота, тип **Secret**;
   - `CHAT_ID` — число из шага 2;
   - `ALLOWED_ORIGIN` — `https://enikonov565-cloud.github.io`
     (адрес сайта без пути и без `/` в конце; можно несколько через запятую).
5. Скопируйте адрес Worker, например `https://lisa-brief.имя.workers.dev`.

### Шаг 4. Указать адрес на сайте
Откройте `config.js` и вставьте адрес:

```js
window.BRIEF_CONFIG = {
  endpoint: 'https://lisa-brief.имя.workers.dev'
};
```

Закоммитьте и опубликуйте. Пройдите бриф сами — в Telegram придут сообщения.

### Как выглядят сообщения
1. **Сводка**: имя, контакт (ник — кликабельная ссылка), вид съёмки, цель,
   количество людей, локация/студия, бюджет, сроки, номер брифа.
2. **Каждый этап — отдельным сообщением**, вопросы жирным.
   Вопросы без ответа не показываются.
3. Длинные ответы режутся по абзацам, затем по строкам и предложениям — никогда
   не посреди фразы. Лимит Telegram — 4096 символов на сообщение.
4. Приложенные файлы приходят следом документами (без сжатия) с подписью
   «Референс 1/3 · Имя · № брифа». Если файл не дошёл, текст брифа всё равно
   уже у вас, а клиент на финальном экране увидит просьбу прислать файл в Telegram.

## 4. Как менять вопросы

Всё в начале `app.js`, остальной код трогать не нужно.

**Этапы** — массив `STEPS`:
```js
{ id: 'idea', title: 'Настроение и идея', description: 'Пояснение под заголовком' }
```

**Вопросы** — массив `QUESTIONS`:
```js
{
  id: 'mood',            // уникальное имя, латиницей
  step: 'idea',          // id этапа
  label: 'Какую атмосферу…?',
  hint: 'Подсказка под вопросом',   // '' — без подсказки
  required: true,        // обязательный
  key: true,             // плашка «важно»
  type: 'textarea',      // 'textarea' | 'text' | 'choice' | 'files' | 'links'
  options: ['А', 'Б'],   // для 'choice'
  multi: true,           // можно выбрать несколько
  other: true,           // поле «свой вариант»
  placeholder: '…',
  showIf: { id: 'shootType', equals: 'Студийная' },  // показывать только при таком ответе
  summary: 'Бюджет'      // попадёт в первое сообщение-сводку под этой подписью
}
```

- Добавить вопрос — вставьте объект в нужное место массива.
- Удалить — удалите объект.
- Новый этап — добавьте его в `STEPS`, счётчик «01 / 07» и точки пересчитаются сами.
- Количество и размер файлов, ссылка на Telegram и политику — в объекте `SETTINGS`.

> Если сильно поменяли вопросы, поменяйте и `draftKey` в `SETTINGS`
> (например, `lisa-brief-draft-v2`), чтобы старые черновики не смешались с новыми.

## 5. Публикация на GitHub Pages

1. Создайте репозиторий (например, `brief`) и загрузите все файлы этой папки.
2. **Settings → Pages → Deploy from a branch → main / (root)**.
3. Бриф будет доступен по адресу `https://enikonov565-cloud.github.io/brief/`.

Проверить локально можно любым статическим сервером, например:
```bash
npx serve .
```

## 6. Документы в подвале

С основного сайта перенесены контакты и **Политика обработки персональных данных**
(других документов на сайте пока нет). Когда появятся оферта, отдельное согласие
и реквизиты ИП — добавьте ссылки в `index.html`, блок `foot__col` «документы»:
там оставлен закомментированный шаблон.

**Важно до подключения Worker:** в текущей политике написано, что заявки приходят
на почту и данные никуда не передаются. С брифом данные идут через Cloudflare
в Telegram — обновите разделы 2, 5 и 6 политики, прежде чем включать отправку.
